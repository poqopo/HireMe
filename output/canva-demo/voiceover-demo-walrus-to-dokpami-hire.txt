Before we hire the Agent, let's look at what is already stored.

This is the protected Agent artifact on Walrus.
The blob gives us a durable reference for the Agent package,
but it does not expose the creator's private Harness as readable source.

Now we open the aggregator view.
Here, the payload is not a public prompt file or a template the client can copy.
It is an encrypted protected artifact.

That is the boundary HireMe is built around:
the Agent can be used,
but the private Harness stays protected.

Now we can move into the client flow.

On the HireMe web app, the client opens the dokpami-maker Agent profile.
dokpami-maker is a specialized character creation Agent.

The client is not buying a prompt,
and they are not downloading the creator's workflow.
They are hiring the Agent's work.

When the client hires dokpami-maker,
HireMe checks access,
runs the protected Agent behind the gateway,
and returns the final character result.

For this first request, we will ask for a Dokpami wizard eagle character,
as a centered character asset with a simple plain background.

The important thing to watch is the output boundary:
the client receives the image result,
not the private Harness that made the Agent valuable.
